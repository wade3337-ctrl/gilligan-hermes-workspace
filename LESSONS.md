## 🗄️ DB / SQL (TRIM IT, sqlcmd via gsql.sh)
- ⚠️ **The GSTS play SQL box is SHARED and gets hammered by daytime SSMS load** — a heavy analytical query (retention sessionization) ran **<1s when the box was quiet** but **timed out (>4–5 min)** minutes later while someone ran heavy work in SSMS. `sqlcmd "Timeout expired"` = a **QUERY** timeout (server too slow), **NOT** a network drop — confirmed the tailnet was direct/0%-loss the whole time. → schedule heavy/analytical runs **OFF-PEAK (3am PT)**; don't reboot the box chasing a network ghost. (2026-07-15)
- ⚠️ **A proc/view "deployed" per the notes may NOT actually be on the server** — `ret.vRetentionTrend` (054) was written + bug-fixed in the .sql file but its `OBJECT_ID` was NULL (never applied). → `SELECT OBJECT_ID('schema.obj')` for every object before validating, and redeploy from the .sql files. (2026-07-15)
- ⚠️ **`gsql.sh` takes a FILE or STDIN, not an inline arg string** (it `cat`s $1) → pipe SQL on stdin. (2026-06-21)
- ⚠️ **`gsql.sh` writes ONE shared remote temp file** → concurrent queries clobber each other → run **sequentially**
  or use a per-process isolated wrapper. (2026-06-21)
- ⚠️ **Reserved words as a column alias break sqlcmd** ("Incorrect syntax near 'proc'") → use a safe alias (`pname`). (2026-06-21)
- ⚠️ **`SUM(CASE WHEN EXISTS(subquery)…)` / aggregate over a subquery → SQL error 130** → compute the per-row flag in a CTE/derived table, then `SUM()` it. (2026-06-25)
- ⚠️ **`dbo.ZoneDefs.ColorCode` TEXT is a useless uniform 'Yellow' on every zone — the REAL per-zone color is `ColorDefID` → `dbo.ColorDefs.ColorCode` hex** (Green/Orange/Blue/Red matching the printed map). First zone-importer preferred the text field → every area came out yellow. → resolve color via ColorDefID, fall back to the text only if the FK is null. (Reverses an earlier wrong call to "trust zd.ColorCode text.") (2026-07-07)
- ⚠️ **sqlcmd (gsql.sh) truncates `varchar(max)` at 256 chars** → a long value (e.g. `ZoneDefs.FusionTablePolygon` KML, up to ~2KB) comes back cut off. → fetch it in ≤160-char **bracket-wrapped** chunks (brackets survive `-W` trailing-trim) + reassemble in Python. (2026-07-07)
- ⚠️ **Some TRIM IT `ZoneDefs` rows are junk** — C2E Townhomes (1283100) had 5 *identical duplicate* polygons + 1 that parses to 0 points, all one color. The pretty multi-color map was hand-drawn onto the image, NOT saved as data. → before trusting a site's zones, check for distinct geometry; don't assume the colorful map == pullable vector data. (2026-07-07)
- ⚠️ **A literal `#` in ANY double-quoted CFML string = "missing ending #" / interpolation error — NOT just inside `<cfoutput>`** (also `<cfset x="...#77...">`, array literals, etc.). Bit me twice in one day (inline `color:#fff`, then `#77` inside a `cfset` repairRows array). → escape as `##`. (2026-06-25)

## 🗄️ Legacy-DB → Postgres pipeline + pricing engine (2026-07-01)
- ❌ **Windows `sqlcmd` output is CRLF → breaks Postgres `\copy … FORMAT csv`** with "unquoted newline found in data" (the trailing `\r` corrupts the last field / row boundary). Always `tr -d '\r'` between the gsql pull and the COPY. (Cost one failed load before spotting it.)

## 🔐 HermanRO DB access broke nightly, silently (2026-07-03)
- ❌ **`sqlcmd` without `-b` exits 0 even when the SQL errors** — so a Windows scheduled task (or any wrapper checking exit code) shows "success/Result 0" while its `CREATE USER`/`ALTER ROLE` fails every run. The re-grant job "ran fine" for days while Boss Herman's DB user stayed missing. ALWAYS pass `-b` on any sqlcmd that mutates, and log its output — exit code alone lies.
- ❌ **`NT AUTHORITY\SYSTEM` is NOT a SQL sysadmin by default** — a schtask running `sqlcmd -E` as SYSTEM couldn't `CREATE USER`. Don't assume SYSTEM = DB admin. Fix without escalating the box: drive the grant from a host that already has a sysadmin login (we run it from gilligan as Administrator on a cron).
- 🔁 **Restoring a DB from another instance ORPHANS/wipes its db-level users** (server logins survive, database users don't). Anything granted at the *database* level (users, role membership) must be re-applied AFTER every restore. Cost me ~3 iterations (all-zeros results).

## [security/ssh] rsync key rejected → SSH password fallback BYPASSES the forced-command restriction (2026-07-16)
MuniBot 200GB drop: cwRsync's ssh rejected the drop key (Windows ACLs too open) → **fell back to password auth**, which SUCCEEDED for wade3337 → the per-key `command="rrsync -wo <warehouse>"` restriction **did NOT apply** (forced commands are key-scoped) → rsync ran unconfined against `~/` (dumped empty cygwin stub dirs; caught before real data). **Fixes:** (client) `icacls <key> /inheritance:r /grant:r "%USERNAME%:R"` so ssh accepts the key, AND force `-o PreferredAuthentications=publickey -o BatchMode=yes -o NumberOfPasswordPrompts=0` so it FAILS SAFE instead of using a password. (server) `PasswordAuthentication no` — a key-only box should never allow password login to bypass a write-only drop. **Rule:** any forced-command/restricted-key drop is only as safe as `PasswordAuthentication no`; verify it. Detection: `journalctl -u ssh | grep "Accepted password"`.

- [trimit/dashboards] **Changing a SHARED data structure broke a sibling page.** Reworked `woByCo` in `CityBudgets.data.cfm` (struct-of-labels → array-of-rows) for the scope-guard fix; `CityBudgetsRenewals.data.cfm` *reuses* that same `woByCo` (per its header comment) and still did `StructKeyExists(woByCo[cid], label)` → runtime error at line 49, blanking the whole Renewals tab. **Lesson:** before changing any structure built in one page and consumed by others, `grep` every consumer FIRST and update them in the same change-set + render-verify EACH sibling. - [security/ssh] **cwRsync bundles can be STRIPPED — don't depend on `cygpath`/`chmod` in the launcher.** MuniBot local-source drop (v5): the Desktop cwRsync bundle had `rsync.exe`+`ssh.exe`+`cygwin1.dll` but NOT `cygpath.exe`/`chmod.exe`. The `.cmd` used `cygpath -u` to translate the key's Windows path → cygwin form; with cygpath missing that step silently produced an EMPTY string → `ssh -i ''` → "Identity file not accessible" → `Permission denied (publickey)`, transfer never authenticated. **Fix:** translate paths in pure batch (`set DL=%P:~0,1%` + `set REST=%P:~2:\=/%` → `/cygdrive/%DL%%REST%`), lowercase the drive letter, drop the `chmod 600` (rely on `icacls /inheritance:r /grant:r user:R` for cygwin-ssh key perms), and BUNDLE `munibot_drop_key` in the zip so it's guaranteed beside the launcher. **Rule:** a Windows rsync launcher should assume only rsync.exe+ssh.exe+cygwin1.dll exist; never call cygpath/chmod/other cygwin coreutils that may be absent.
