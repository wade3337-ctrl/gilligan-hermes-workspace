## 🗄️ DB / SQL (TRIM IT, sqlcmd via gsql.sh)
- ⚠️ **`gsql.sh` takes a FILE or STDIN, not an inline arg string** (it `cat`s $1) → pipe SQL on stdin. (2026-06-21)
- ⚠️ **`gsql.sh` writes ONE shared remote temp file** → concurrent queries clobber each other → run **sequentially**
  or use a per-process isolated wrapper. (2026-06-21)
- ⚠️ **Reserved words as a column alias break sqlcmd** ("Incorrect syntax near 'proc'") → use a safe alias (`pname`). (2026-06-21)
- ⚠️ **`SUM(CASE WHEN EXISTS(subquery)…)` / aggregate over a subquery → SQL error 130** → compute the per-row flag in a CTE/derived table, then `SUM()` it. (2026-06-25)
- ⚠️ **`dbo.ZoneDefs.ColorCode` TEXT is a useless uniform 'Yellow' on every zone — the REAL per-zone color is `ColorDefID` → `dbo.ColorDefs.ColorCode` hex** (Green/Orange/Blue/Red matching the printed map). First zone-importer preferred the text field → every area came out yellow. → resolve color via ColorDefID, fall back to the text only if the FK is null. (Reverses an earlier wrong call to "trust zd.ColorCode text.") (2026-07-07)
- ⚠️ **sqlcmd (gsql.sh) truncates `varchar(max)` at 256 chars** → a long value (e.g. `ZoneDefs.FusionTablePolygon` KML, up to ~2KB) comes back cut off. → fetch it in ≤160-char **bracket-wrapped** chunks (brackets survive `-W` trailing-trim) + reassemble in Python. (2026-07-07)
- ⚠️ **Some TRIM IT `ZoneDefs` rows are junk** — C2E Townhomes (1283100) had 5 *identical duplicate* polygons + 1 that parses to 0 points, all one color. The pretty multi-color map was hand-drawn onto the image, NOT saved as data. → before trusting a site's zones, check for distinct geometry; don't assume the colorful map == pullable vector data. (2026-07-07)
- ⚠️ **A literal `#` in ANY double-quoted CFML string = "missing ending #" / interpolation error — NOT just inside `<cfoutput>`** (also `<cfset x="...#77...">`, array literals, etc.). Bit me twice in one day (inline `color:#fff`, then `#77` inside a `cfset` repairRows array). → escape as `##`. (2026-06-25)
- ⚠️ **Don't BATCH the live `Reference-RepairsAndScheme.cfm` sync** — update its `repairRows`/`buildRows` when you write each `gsts-ship-log.md` row, not "later." Let it drift 13 entries behind once (Skipper caught it). Edit it byte-level (ASCII-only inserts after a newline) since it's UTF-8 + may have a BOM. (2026-06-25)

## 🗄️ Legacy-DB → Postgres pipeline + pricing engine (2026-07-01)
- ❌ **Windows `sqlcmd` output is CRLF → breaks Postgres `\copy … FORMAT csv`** with "unquoted newline found in data" (the trailing `\r` corrupts the last field / row boundary). Always `tr -d '\r'` between the gsql pull and the COPY. (Cost one failed load before spotting it.)
- ❌ **Postgres has NO `round(double precision, int)`** — only `round(numeric, int)`. `ROUND(col * %s, 4)` where `%s` is a Python float makes the product `double` → "function round(double precision, integer) does not exist". Cast: `ROUND((col * %s)::numeric, 4)`. (Python-side `round()` before insert sidesteps it.)
- ❌ **browserless `/function` returns an EMPTY 200 unless the module returns `{data, type}`** (a bare object/value serializes to nothing). And `page.waitForTimeout` is gone in newer Puppeteer → `await new Promise(r=>setTimeout(r,ms))`.
- ❌ **Substring checks on human-readable labels collide.** Fallback-tier logic keyed on `"species" in label` wrongly fired for the label `"size (any species)"` (contains "species"), so a species-agnostic aggregate mislabeled itself with a random `MIN(species)`="Acacia". Use explicit boolean flags per tier, never substring-match a display string for control flow.

## 🔐 HermanRO DB access broke nightly, silently (2026-07-03)
- ❌ **`sqlcmd` without `-b` exits 0 even when the SQL errors** — so a Windows scheduled task (or any wrapper checking exit code) shows "success/Result 0" while its `CREATE USER`/`ALTER ROLE` fails every run. The re-grant job "ran fine" for days while Boss Herman's DB user stayed missing. ALWAYS pass `-b` on any sqlcmd that mutates, and log its output — exit code alone lies.
- ❌ **`NT AUTHORITY\SYSTEM` is NOT a SQL sysadmin by default** — a schtask running `sqlcmd -E` as SYSTEM couldn't `CREATE USER`. Don't assume SYSTEM = DB admin. Fix without escalating the box: drive the grant from a host that already has a sysadmin login (we run it from gilligan as Administrator on a cron).
- 🔁 **Restoring a DB from another instance ORPHANS/wipes its db-level users** (server logins survive, database users don't). Anything granted at the *database* level (users, role membership) must be re-applied AFTER every restore. Poll/re-grant on a schedule tighter than the restore cadence, and prove it by simulating the wipe (DROP USER → verify broken → re-grant → verify fixed).

## 🤖 Don't run high-volume intake INSIDE the agent's live conversation (2026-07-03)
- ❌ **The Hermes email gateway adapter is a two-way email *assistant*** — it feeds inbound mail into the agent's ONE live conversation and auto-replies to the sender. A 6-email burst tangled the requests ("all three drafted"), spam-looped on our OWN test inbox (verified: 0 real-customer addresses ever), and JAMMED Boss Herman (required a restart). A skill-level "delegate + report to Telegram" rewire could NOT override the adapter's structural behavior.
- ✅ **Fix = a standalone background service** (`rfp-watcher.py` cron + `rfp-intake.py`) that uses the agent's TOOLS/crew but runs ONE isolated OS process per email (parallel-safe), reports to Telegram via the bot API, never touches the customer thread or the agent's live chat.
