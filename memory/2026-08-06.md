### THE ROOT CAUSE (cracked by reading dist source, not docs)
Windows headless node ALWAYS boots security=`allowlist` — `resolveExecSecurity(void 0)` returns `"allowlist"` as the hard default (node-cli-*.js). In allowlist mode, `windowsShellWrapperBlocked = security==="allowlist" && shellWrapperInvocation && isWindows && cmdInvocation` → **every cmd.exe command is blocked → SYSTEM_RUN_DENIED: approval required.** The runtime security is LAYERED: `applyExecPolicyLayer({security:allowlist(default)}, cfg.tools?.exec)` — i.e. it reads the **NODE MACHINE's OWN `tools.exec` config** and layers over the allowlist base. Setting the GATEWAY's tools.exec or the exec-approvals.json FILE = wrong layer (never reached the node).

### THE FIX (both required simultaneously)
1. **On the laptop:** `openclaw config set tools.exec.mode full` (persists; `mode` is exclusive with security/ask — don't set all three, that errors). This makes the node boot full instead of allowlist.
