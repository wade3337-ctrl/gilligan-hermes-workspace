## Zone import built (`importer/bidqueue_import.py`)
- New `pull_site_zones(site_id, location_id)`: TRIM IT `dbo.ZoneDefs.FusionTablePolygon` (KML) → arbor-core `site_area` rows so a pulled job **arrives with its real color-coded work areas already drawn** (no manual map-extraction). `source='trimit_zone'`.

  - ZoneDefs `Desc1` is often a bare number that **repeats** → global name de-dup (`"1"`, `"1 (2)"`…) so every polygon survives the `lower(name)` unique index.

## Area extraction test → found the real color bug (+ a corrupt test job)
- Skipper compared the TRIM IT trimming map (yellow/orange/blue/green areas) vs arbor-core's "Extract areas" AI attempt (a broken orange triangle). Asked why the areas didn't come over.
- **Teaching:** "Extract areas" = AI *tracing* areas off the map picture (unreliable). We don't need it — the real areas are saved as polygons in TRIM IT (`ZoneDefs`), which the new importer pulls directly.
- **Finding 1 — the job he tested (C2E Townhomes 1283100) has CORRUPT zone data:** 5 identical duplicate polygons + 1 that parses to 0 points, all one color. The 4-color map was hand-drawn onto the image, not saved as data. → C2E is a bad "areas" test case.
- **Finding 2 — the real bug (commit 3fc4365):** `ZoneDefs.ColorCode` text = uniform 'Yellow' on every zone; the true per-zone color is `ColorDefID` → `ColorDefs` hex. Importer read the text → all-yellow zones. Flipped to `ColorDefID`. **Verified Nellie Gail (1273810): 4 distinct colors** — Exterior=Green(393 trees), Perimeter=Orange(66), Hedge=Blue(93), Crew Rental=LightGreen(9). Headless screenshot confirms they render on the GIS map.
