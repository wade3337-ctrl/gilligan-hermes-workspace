## Lesson
- **"The application did not respond" on Discord = OpenClaw's 180s no-output watchdog killing my turn.** Confirmed in
  gateway log 2026-06-30: `reason=timeout — CLI produced no output for 180s and was terminated` at 01:45 & 01:53,
  both when **kimi-ask ran as a long FOREGROUND blocking Bash call** (slow reasoning model, >180s silent). The turn
  dies mid-reply → Discord shows "application did not respond" (exit 137). NOT message-preemption (my earlier wrong
  guess), NOT a crash/network issue — gateway stayed up. **Fix:** never run a slow model (kimi) as a long blocking
  foreground call; use glm/gemini in-line, or background kimi so it can't starve the turn's output stream.
- gemini-ask reads STDIN only (no file-path arg); glm/kimi accept a numeric max_tokens arg + file path.
