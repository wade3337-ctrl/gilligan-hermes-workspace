## TABLET READINESS

Caveat repeated: I could not resize the window, so this is inferred from CSS and measured layout rather than observed.

`assets/css/main.css` (27,546 chars) contains exactly **one** media query — `@media (max-width: 767.98px)`, used 14 times. There is no tablet breakpoint at all. Inside it, `.sidebar` flips to `width: 100%` and stacks, so a phone layout does exist and the DOM carries mobile-specific duplicates (I found duplicate Zones/Districts checkboxes served for the mobile panel, and the console logs a separate "mobile context" search init).

The consequence is that **~800px is the worst possible width**: it's above 767.98px, so the desktop layout applies in full. Measured live, `.sidebar` is a hard `width: 350px; flex: 0 0 350px`, and the left nav is a fixed `250px`. That's 600px of immovable chrome. At an 800px viewport roughly 200px would remain for the content column — the projects table (five columns, one holding two-line addresses) and the Map Setup canvas would both be crushed. The Artwork page is worse: its page canvas is sized in absolute print pixels (the 17×11 layout is `1620x1040`), so it will overflow horizontally regardless.

There are two mitigations, and they're real: a "Collapse menu" control on the left nav and a "Hide sidebar" chevron on the filter rail. Used together they'd recover most of the width — but that's a manual workaround on every page load, not responsive design. A crew on an iPad in portrait will be pinching and scrolling horizontally.

## OVERALL

This is much further along than "prototype" — the eight-step wizard, the boundary editor's per-shape tooling, the Artwork layout designer and especially Field App BETA are real, well-crafted software with thoughtful tooltips, sensible guard rails, a clean JSON API, and zero application JavaScript errors across every page I touched. Architecturally it's a genuine rebuild rather than a reskin, with the notable exception of the Artwork tab (eight legacy `Tan/Wizard-Map-*.cfm` iframes) and the Pricing Worksheet (an old WebPortal page in new clothes). I'd estimate it's a handful of focused bug fixes plus a data-backfill away from being demonstrable, but not yet field-ready: fix the coordinate handling and the fit/saved-view logic, add a tablet breakpoint or make the two panel-collapse states sticky, change "Add Contact" to stop inserting records before the user types, and give the note flags a visible on/off state.
