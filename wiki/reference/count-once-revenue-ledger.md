# Count-Once Revenue Ledger — path-to-goal methodology

The **coverage model** behind the [[deal-tracker-dashboard]]: how far the 2026 revenue goal is *covered* vs. still needs new sales — with **every dollar counted exactly once**. Designed from Boss Herman's spec (7/21) + Gilligan's live reconciliation (7/22). Regenerated by `business-plan/refresh-deal-dashboard.py`. Proof-of-work: `business-plan/count-once-ledger-2026-07-22.md`.

## The bridge (5 layers, no overlap)
`Goal − [ Adjusted Actual + Muni Forecast + Firm Sold + Risk-adj Pipeline ] = Uncovered Gap`

| Layer | Source (live) | Notes |
|---|---|---|
| **Goal** | `dbo.GoalSettings` ZUserID=9 `MonthlyGoal`×12 | Skipper 7/22 chose this ($25.05M, flat) over `Workbench.SalesGoal` monthly shape ($25.19M). |
| **Adjusted Actual YTD** | `Invoices`×`Periods` (acct period) + accrual bridge | see basis + accrual below |
| **Municipal Forecast (rem.)** | City Budgets forecast engine (live CSV) | Skipper chose **calendar-H2 $3.74M** (config) over engine FY-remaining ~$2.22M; engine budget−invoiced recon ~$3.19M. → [[city-forecasting]] |
| **Firm Sold Coverage** | `WorkOrders` StatusDefID IN (46,109), `DateCompleted` NULL, `EstValue`>0, `EndDate` today..12/31, non-muni | undated/beyond-year → separate "Needs Production Date" queue, NOT coverage |
| **Risk-adj Fresh Pipeline** | `GoAheads` StatusDefID=49, `Created`≥−90d, deduped MAX(EstValue)/project, HOA/Comm/PM (Markets 5,6,16) × 40% | conversion % configurable |

## Financial-actual basis (Herman, adopted)
- **Accounting period, not invoice date:** `Invoices.PeriodID → Periods.StartDate`.
- **Status filter:** `StatusDefID IN (21,100,22,23,148)`, `IsProForma=0`, `IsCredit=0`.
- Old board's InvoiceDate+unfiltered was ~$66K high.
- **Accrual bridge:** Adjusted = invoiced + current-period accrual − Dec-prior-year accrual. Live from [[trimit-accrual-formula]] (the corrected muni accrual). Current period is partial-month (accrual grows to month-end).

## Municipal classification (the count-once linchpin)
`dbo.ProjectGroups.ProjectGroupDefID = 11` (NOT "City of" name-matching). Validated: muni invoiced YTD = **$4,192,062** = Herman's TRIM IT figure to the dollar. Firm/pipeline layers EXCLUDE muni via `NOT EXISTS`; muni forecast is contract budget (not scheduled crew) → the layers can't double-count each other.

## Count-once hard rules (honored)
Pending proposals >90 days excluded · undated sold work quarantined until Production dates it · duplicate GoAhead revisions deduped (MAX/project) · never add GoAheads + their WorkOrders wholesale · **production board (CrewSheets) ≠ accounting actual** (kept off the financial ledger).
