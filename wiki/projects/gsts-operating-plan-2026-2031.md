# 🏗️ GSTS Operating Plan 2026-2031 (BLACK)

**One-liner:** The **company's** operating plan (Skipper's call: not a personal pitch) — companion to `GSTS-50M-Growth-Plan.md`.
**📁** `business-plan/GSTS-Operating-Plan-2026-2031.md`
**Status:** 🔵 drafted 2026-07-24; §3B = the vendor-build assessment.

## The core hook
> The growth plan promises **EBITDA 20% → 25%** and never says **HOW**. That's **$2.5M/yr = $25–30M of enterprise value**. **This plan is the mechanism.**

## ⚠️ Sequencing rule (locked)
**Earnouts (2026-27) run on AGP, which EXCLUDES overhead** → do **revenue / field work FIRST**; overhead work pays at **exit** (EBITDA). Don't invert it. See [[gsts-2026-earnout]].

## Phases
| Phase | When | What |
|---|---|---|
| **0** | now → close | build capacity to execute |
| **1** | 2027 | AGP / earnout — revenue + field |
| **2** | 2028-29 | decouple overhead from revenue |
| **3** | 2030-31 | platform + acquisitions |

**Headline KPI: admin hours per $1M revenue — today 228, target ≤100.**

## Phase-1 reality check
Phase 1 is **NOT greenfield.** The vendor has a real Field App rebuild already standing on the dev box — inherit and finish it. Full assessment + the four critical-path defects → **[[vendor-fieldapp-build]]** (§3B).

## Evidence base
The measured case that this plan rests on — three transcription points, the department bottleneck map, and the cost-of-rekeying model — lives in **[[trimit-investor-case]]**.
