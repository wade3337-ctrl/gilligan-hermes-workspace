🔒 V1 Security Remediation Roadmap

Built from the live read-only sweep (Jun 10). Turns the scary "8,422" headline into a prioritized, mostly-AI plan — and confirms: fix on V1, don't migrate.

Reading the 8,422 honestly (signal vs. noise)

The scan flags any query with an interpolated #variable# and no cfqueryparam. That's the right net to cast — but it's an upper bound of sites to review, not 8,422 live holes. Breaking it down:

  • 🗑️ A large share is dead/temp/dev code sitting in the web root — TravisTemp*, zDataFix*, *_DeleteLater, ZTest2, test1, TestEnv, *Copy*, Jasonsrepairs (174), TanBackup (49). These get DELETED, not fixed — which erases a big chunk of the count and removes risk (they shouldn't be web-reachable at all).
  • 🟡 Many interpolate internal values — loop IDs from a prior query (#DATA.ID[i]#), app constants (#application.dsn#), or ETL table names. Lower risk, batch-fixable, some are false positives.
  • 🔴 The genuinely urgent set is the user-facing subset — WebPortal (1,623, your external customer portal), External$RFP*, API\resources, FieldApp, and the login flow. These take real outside input. This is where we start.
🔑 The #1 move de-risks everything at once. Both datasources (GSTS + GSTSAPI) connect as sa — full SQL Server admin. That means any SQL injection that is exploited runs with god-rights (catastrophic). Replacing sa with a least-privilege login is fast (hours) and instantly caps the blast radius of all ~8,400 sites — even before a single query is fixed. Do this first.

The plan — four tiers

TIER 0Cap the blast radius — days
  • Replace sa on GSTS + GSTSAPI with least-privilege SQL logins.
  • Rotate & vault the exposed secrets found in code (FTP_PASSWORD, apiUser passwords, azureTranslatorKey — 60 spots).
TIER 1Close the front doors — weeks
  • Parameterize SQL injection on the user-facing endpoints first: WebPortal, External$RFP*, API\resources, FieldApp, login. (cfqueryparam / whitelist dynamic identifiers.)
  • Fix plaintext passwords → salted hashing (Argon2/bcrypt); stop the admin screen from displaying stored passwords.
  • Harden auth cookies (Secure/HttpOnly/SameSite) and stop trusting role/identity values stored in client cookies (CurrentUserRoles, IsInternalUser = privilege-escalation risk).
TIER 2Shrink the surface — cheap, parallel
  • Delete the dead/temp/dev files from the web root (backup first). Removes risk + a big slice of the 8,422.
  • Lock down the 78 upload handlers (require auth, extension/MIME allowlist, store outside web root).
  • Strip public cfdump/debug output (298 spots, mostly in junk files).
TIER 3Sweep the rest — ongoing, AI-batched
  • Parameterize remaining internal queries module-by-module (Chrome/Steel/Yellow/Water…).
  • Finish the stored-proc scan — the live read failed on Windows auth; re-run read-only with a SQL login to get the true proc picture (checked-in scripts showed 5/59 dynamic-SQL).
  • Roll into the broader V1.5 cleanup (foreign keys, dead-table retirement).
